# Слизевик‑поля

## Идея
Интерактивная симуляция «слизевика»: множество агентов движутся по двумерному полю, считывают «химические» следы, оставляют депозит, а поле диффундирует и испаряется. Пользователь воздействует кистями (притяжение/отталкивание), рисует стены, ставит на паузу, сбрасывает сцену.

## Технологический стек
- TypeScript (ES2022, строгая типизация)
- Vite (dev‑сервер и сборка)
- Canvas 2D API (рендеринг)

## Архитектура UI

- **Построчная система (rows + units)**
  - Каждый ряд имеет фиксированную высоту `layout.rowHeight`. 1 юнит = `rowHeight - 2*gap`.
  - Ширина контрола с `units = N` равна `N*unit + (N-1)*gap`. Это гарантирует выравнивание колонок между рядами.
  - Если контролы не помещаются по ширине, ряд горизонтально скроллится.
  - Кнопка‑попап показывает связанный тулбар в следующем ряду выше. Вложенность управляется стеком `openPath`.

- **Состав**
  - `ui-config.ts` — декларативное описание базового ряда и вложенных тулбаров.
  - `ui-builder.ts` — рендерит ряды снизу вверх по `openPath`, вычисляет размеры в юнитах.
  - `ui-controller.ts` — хранит состояние (`tool`, `paused`, `tempo`, `openPath`), эмитит события: `toolChange`, `pauseChange`, `tempoChange`, `popupAction`, `openPathChange`.
  - `styles.css` — стили рядов и контролов. Перетаскивание слайдера имеет приоритет над скроллом ряда.
  - `app-config.ts` — не‑UI параметры (canvas/DPR, HUD, анимации, инструменты).

- **Адаптив**
  - `main.ts` измеряет фактическую высоту `#ui-rows` и вычитает её при подборе размера поля.

### Добавление контрола

Пример добавления кнопки и слайдера в `ui-config.ts` в базовый ряд:

```ts
export const UI_CONFIG = {
  layout: { rowHeight: 56, gap: 8 },
  toolbar: [
    { id: 'myButton', type: 'button', title: 'Действие', icon: '⚡', units: 2 },
    { id: 'mySlider', type: 'slider', title: 'Порог', min: 0, max: 1, step: 0.05, defaultValue: 0.5, units: 3 },
    { id: 'settings', type: 'popup', title: 'Настройки', icon: '⚙️', units: 1, toolbar: [
      { id: 'flag', type: 'toggle', title: 'Флаг', icon: '🏁', units: 2 },
    ]},
  ]
} as const;
```

## Основные команды
- `npm run dev` — локальная разработка (Vite, автообновление).
- `npm run build` — прод‑сборка в `dist/`.
- `npm run preview` — предпросмотр прод‑сборки на `http://localhost:5173`.
- `npm run deploy` — сборка и копирование артефактов на сервер (использует `copy`).

## Принципы цветовой индикации
Ниже описаны принципы, по которым формируется визуальная индикация, без привязки к конкретным цветовым кодам:

- **Нулевой уровень поля**: отображается близким к фону и малоконтрастным, чтобы не отвлекать и не «заливать» экран. Это создаёт нейтральный холст, на котором видны изменения.

- **Двухполярная палитра поля**: значения поля разделены на две ветки с разными цветовыми семействами. 
  - **Положительные значения**: индиго → лаванда; яркость/насыщенность монотонно растут с модулем значения.
  - **Отрицательные значения**: глубокий тин → аква; яркость/насыщенность также зависят от модуля.
  - **Компрессия динамического диапазона**: используется гамма‑коррекция для лучшей перцептивной градации и избежания пересветов; значения поля клэмпятся в допустимые пределы.

- **Следы vs агенты**: статичные следы и динамические агенты визуально разведены по слоям и стилю.
  - **Следы**: интегрируются в палитру поля (теплохолодовая карта) и подчиняются её яркости.
  - **Агенты**: ледяной циан поверх поля отдельным контрастным оверлеем, с лёгкой временной модуляцией (мерцанием). Для направления добавляется мягкая циановая «искра» впереди по вектору движения.
  - **Режим смешивания**: поверхностное «осветляющее» смешивание (по сути, выбор максимальной яркости по каналам) гарантирует, что агент не потеряется на ярком следе.

- **Стены/препятствия**: показываются устойчивым нейтральным тоном с низкой насыщенностью. По яркости они отделимы от фона, но не конкурируют с агентами и активными участками поля.

- **Читаемость и баланс**:
  - Насыщенность и контраст регулируются параметром гаммы и порогами яркости, чтобы сохранять текстуру следов, но не забивать движущиеся объекты.
  - Избегаем больших однотонных заливок: начальное состояние — нейтральное, без градиентов, чтобы пользовательская активность и динамика системы были первичны визуально.

Эти правила обеспечивают: нейтральный фон, читаемую карту концентраций, явную видимость агентов и их направления, а также скромную, но различимую индикацию стен.
